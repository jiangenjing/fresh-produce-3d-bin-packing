## 研究问题

生鲜产品尺寸差异大，装载既要减少使用的容器数量，也要提高空间利用率。论文讨论支撑稳定性、易损性、承重和卸货等现实需求；**不能由这些业务描述推断提交代码已完整实现所有约束**。

模型以货物尺寸、位置和摆放方向表示方案，核心几何条件为不越界、不重叠与支撑可行性。优化目标在启发式搜索中体现为容器数量、可放置性和利用率等评价；不是具有全局最优保证的精确算法。

## 方法链路

1. 初始化货物与订单，组织候选箱体。
2. 构造组合块，减少逐件枚举的搜索空间。
3. 在剩余空间中选择同层放置方案。
4. 通过树搜索 / 束搜索保留部分候选路径，平衡质量与时间。
5. 评价装载结果，保存各箱体坐标与方向。

代码阅读顺序：`domain/main.py` → `dao/data_process.py` → `utils/parameters.py` → `algo/pack_tool.py` → `algo/pack.py` → `entities/entity_object.py`。

### 1. 为什么采用组合块？

如果每一步枚举所有货物、方向与空位，候选数会快速增长。组合块把可一起放置的若干货物组织为一个候选单元，可以减少搜索分支，同时利用尺寸之间的规律。

代价是候选构造规则会限制搜索空间。因此，组合块是一种质量与速度折中，不能保证任何订单都能找到最优解。对大量异形或尺寸差异极大的货物，也需要重新检查块构造的效果。

### 2. 同层放置怎样减少碎片空间？

同层放置围绕相近高度或层面组织货物，便于控制支撑和剩余空间。但是局部填得满，不一定意味着全局箱数最少：当前层的高利用率可能让后续大件无处放置。

因此需要把“放下这一块”放到后续路径中评价，而不是只以当前填充体积贪心选择。

### 3. 树搜索与束搜索保留什么？

一个搜索状态可理解为“已放置货物、剩余货物、可用空间和当前评价”。扩展一个状态会形成多个候选摆法，搜索保留其中部分路径继续探索。

较宽的搜索通常消耗更多时间与内存；较窄的搜索可能更快，但更容易丢失有潜力的路径。具体剪枝、候选排序及参数以归档代码为准，不应从“树搜索”三个字推断使用了完整分支定界或全局最优性证明。

## 怎样判断一个装箱方案有效？

设容器尺寸为 `L × W × H`，货物旋转后的尺寸为 `l_i × w_i × h_i`，位置为 `(x_i,y_i,z_i)`。基本几何检查包括：

$$0\le x_i,\quad x_i+l_i\le L;\qquad
0\le y_i,\quad y_i+w_i\le W;\qquad
0\le z_i,\quad z_i+h_i\le H.$$

任意两个不同货物必须在至少一个轴向上分离。以 x 轴为例，可以是 `x_i+l_i ≤ x_j` 或 `x_j+l_j ≤ x_i`；y、z 轴同理。六种分离关系至少成立一种，才满足轴对齐箱体的不重叠条件。

还需要检查：每件货物恰好使用一次、方向符合允许范围、容器编号有效，以及支撑规则是否满足。二维投影看起来“没有重叠”，不能代替三维几何检查。

### 指标与目标不要混用

| 指标 | 计算或含义 | 应避免的误解 |
| --- | --- | --- |
| 容器数量 | 完成指定订单所用箱/托盘数 | 只优化一个容器的利用率可能增加总箱数 |
| 体积利用率 | 已装体积 / 对应容器体积 | 体积高不自动证明支撑或承重可行 |
| 可行率 | 满足约束的方案比例 | 搜索结束不等于所有约束都通过 |
| 求解时间 | 从确定输入到方案输出的耗时 | 不同设备或时限下的时间不可直接比较 |
| 未装载数量 | 仍未完成放置的货物数 | 排除难装货物会虚高利用率 |

支撑系数可以帮助表达接触支撑要求，但真实承重还涉及材质、重量分布和层间受力。当前材料不能支持“已完整建模全部生鲜易损性约束”的说法。

## 实验设计补充：如何公平比较装箱算法？

比较启发式和精确求解器时，应固定同一批货物、容器、方向约束、支撑条件和时间预算。某个方法允许旋转、另一个不允许，或一个方法遗漏难装货物，会使利用率比较失去意义。建议先用极小算例手工检验，再逐步增加品类数量、尺寸异质性和订单规模。

实验表至少记录箱数、平均与最低利用率、未装数量、可行性错误、运行时间以及停止原因。遇到时限时，应报告当时找到的最好可行解；若精确求解器提供界与 Gap，也应一并保存。“没有在时限内证明最优”不等于“没有找到可用方案”。

几何验证还要约定浮点容差。两个物品边界理论上接触时，数值计算可能出现极小误差；但容差过大会掩盖真实重叠。应统一尺寸单位、误差阈值和独立校验规则。可参考 [Gurobi 的数值容差与尺度说明](https://docs.gurobi.com/projects/optimizer/en/current/concepts/numericguide/tolerances_scaling.html)，理解求解器为何不能按无限精度判断约束。本项目并未据此新增或重跑对照实验。

一个有价值的扩展实验是逐项关闭组合块、同层策略或较宽搜索，观察结果变化。这样能回答每个设计贡献了什么，而不仅是展示最终装载图。所有变化都应保存配置与输入版本；在恢复最终 `test.csv` 之前，不宜发布新的“复现提升率”。
